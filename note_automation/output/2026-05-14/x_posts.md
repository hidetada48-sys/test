## ① X Articles（そのままX Articles機能に貼る）

## 1. CLAUDE.mdに書いたのに、また同じミスをされた

「動作確認してから完了と言え」

そうCLAUDE.mdに書いた2日後、Claudeはまた確認せずに「完了しました」と報告した。

ルールを書く。次のセッションでは守られる。でも3日後には同じミスが戻ってくる。

「ルールを書けば守るはず」——そう思っていた自分の勘違いに気づいたのは、同じミスを8回繰り返された後だった。

## 2. なぜルールを書くだけでは足りないのか

2025年の研究によると、AIエージェントが指示を完璧に守れるのは**30%未満のシナリオのみ**。60個以上のルールを書くと静かに無視が始まる。

Claude自身がこう言っている。

>「ルールは読める。暗唱もできる。ただ従わない。問題は知識ではない。実行だ」

CLAUDE.mdのルールは「知識」として入る。でも「実行の抑止力」にはならない。

## 3. 「ルール」と「失敗記録」は別物

| ファイル | 役割 |
|---------|------|
| CLAUDE.md | 理想形「こうあるべき」 |
| past_mistakes.md | 実例「こうやらかした」 |

「AIは正解より不正解の集合を渡された方が伸びる」

抽象的なルールより、具体的な失敗例の方が刷り込みが強い。

## 4. 実際のミス8件（全部実話）

M-005「Windowsで動くか確認しなかった」をルールとして記録した。

2日後、M-007として全く同じミスが再発した。

ルールを書いた。記録もした。それでも再発した。これが「ルールだけでは足りない」という証拠だ。

他にも：推測で記憶を断言した（M-002）、調査前に「致命的な問題あり」と断言して一言で翻した（M-008）、「たぶん動くはず」で完了報告した（M-004）……

## 5. 作り方は3ステップ

**ステップ1：ファイルを作る**

```
### M-001 タイトル（YYYY-MM-DD）
状況：〇〇をしていたとき
やらかし：〇〇してしまった
対策：次回は〇〇する
```

**ステップ2：CLAUDE.mdの末尾に1行追加**

```
@past_mistakes.md
```

これだけ。v0.2.107から公式のインポート機能が使える。

**ステップ3：ミスが起きたらその場で追記**

次のセッションから自動で読み込まれる。
