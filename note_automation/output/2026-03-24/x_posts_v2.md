# X投稿セット：XブックマークをNotebookLMへ同期するClaudeスキル

生成日：2026-05-10

---

## ① X Articles（そのままX Articles機能に貼る）

XのブックマークをPlaywrightで自動収集し、Claude CodeのスキルでNotebookLMへ同期した。7日間のデバッグを経て完成した記録だ。

## 1. Xのブックマーク、ちゃんと使えてますか？

正直に言います。

私のXのブックマーク、数百件溜まっていました。

「あとで読もう」と思ってブックマークしたツイート。「これは使えそう」と思って保存した記事のリンク。「このコード参考にしたい」と思って押したブックマーク。

全部、眠ったまま。

見返したのは保存した直後だけ。検索しようにも、Xのブックマーク検索は使いづらい。気づいたら「溜めているだけの場所」になっていました。

同じ経験、ありませんか？

ブックマークって本来、自分が価値を感じた情報の集積場のはずです。それが活用できていないのは、もったいないを通り越してもはや損失です。

そこで考えました。

**NotebookLMのソースにできないか？**

NotebookLMは、ドキュメントを読み込ませることで、それを知識ベースとして質問できるGoogleのAIツールです。PDFでも、テキストでも、Google Driveのファイルでも読み込める。

「ブックマークをテキストにしてGoogle Driveに置けば、NotebookLMで使えるんじゃないか？」

そう気づいたとき、このツールを作ることにしました。

## 2. 作ったもの：スラッシュコマンド1発でNotebookLMへ同期するClaude Codeスキル

このツールの一番の特徴は、**Claude Codeのスキルとして実装している**ことです。

Claude Codeには「スキル」という仕組みがあります。SKILL.mdというファイルに手順を書いておくだけで、スラッシュコマンドとして呼び出せるようになります。

つまり、Claude Codeのターミナルで

```
/x-bookmark-to-notebooklm
```

と打つだけで、ブックマークの取得からGoogle Driveへのアップロードまで全部動く。コマンドを覚える必要はありません。スクリプトの場所を探す必要もありません。Claude Codeを開いて、スラッシュを打てばいい。

フローはシンプルです。

```
① Claude Codeで /x-bookmark-to-notebooklm を実行
② PlaywrightがヘッドレスブラウザでXにアクセス
③ ブックマーク一覧をスクロールしてURLを収集（フェーズ1）
④ 各ツイートのページを開いて全文を取得（フェーズ2）
⑤ テキストファイルとして保存
⑥ rcloneでGoogle Drive（X-Bookmarks-NotebookLMフォルダ）へアップロード
⑦ NotebookLMでそのフォルダを参照 → 検索・質問できる
```

NotebookLM側は最初に一度だけフォルダを追加する設定をすればOKです。以降は⑦のステップは不要で、自動的に最新のファイルが反映されます。

## 3. Xブックマークから取れるコンテンツ5パターン

Xには実はいくつかのコンテンツ形式があります。このツールは以下の5パターン全てに対応しています。

| パターン | 取得状況 |
|---|---|
| 通常ツイート | ✅ |
| X長文記事 | ✅ |
| 通常ツイート ＋ 引用通常ツイート | ✅ |
| 通常ツイート ＋ 引用X記事 | ✅ |
| 通常ツイート ＋ 外部リンクカード | ✅ |

noteの記事リンクが貼ってあるツイートも、Qiitaの技術記事リンクが貼ってあるツイートも、外部ページの本文（最大5000文字）まで取得します。

X長文記事（X Article）は1件で**35,803文字**でした。通常ツイートが140文字であることを考えると、ケタが違います。これがNotebookLMの知識ベースに入るわけです。

引用ツイートも、引用元の内容ごと保存されます。エンゲージメント数（リツイート数・いいね数）まで保存されているので、NotebookLMに「バズっていた記事を教えて」と聞けば、この数字を根拠に答えてくれるようになります。

「もっと見る」ボタンも自動でクリックして、省略なく全文を取得します。

初回動作確認時の実績：**50件・14.6KiB・19秒でGoogle Driveへアップロード完了。**

## 4. デバッグ地獄：7日間バグとの戦い

完成形だけ見るとシンプルに見えるツールですが、開発中はバグの連続でした。7日間、毎日何かが壊れていました。

**バグ①：長文が途中で切れる**
一覧ページでは「続きを読む」で省略されているため表示された文字しか取れない。解決策は**2フェーズアーキテクチャ**への変更。フェーズ1でURLだけ収集し、フェーズ2で各詳細ページから全文を取得する方式に切り替えた。

**バグ②：スクリプトは正常終了なのにファイルが空**
原因は「ページは表示されたけど、要素がまだDOMに出現していない」というタイミング問題。Xのページは読み込み完了後も、JavaScriptが非同期でコンテンツを描画する。`wait_for_selector` で要素が出現するまで最大15秒待機することで解消。

**バグ③：@daifukujinjiが消えた日**
6番目のブックマークが別の人のツイートに化けていた。原因はXの**DOM仮想化**。`page.keyboard.press('End')` で一気にスクロールすると中間のツイートがDOMから消える。`window.scrollBy` を使って0.8画面分ずつゆっくりスクロールする方式に変更して解決。

**バグ④：削除済みだと思ったらX記事だった**
通常ツイートは `[data-testid="tweetText"]` で取れるが、X記事はそのセレクタが存在しない別構造。2段階フォールバックで自動判別するように実装した。

**バグ⑤：成功率50%**
2フェーズ実装直後のテストで2件中1件しか取れない。Xのスクレイピング検知対策として各ツイートへのアクセスに**2秒間隔**を設けて改善。

**バグ⑥：コードは正しいはずなのに引用ツイートが全27ファイルで0件**
これが一番頭を抱えたバグ。コードは引用ツイートを取得できていたのに、保存時のマーカーの書き方が想定と異なっていて後から検索しても見つからなかった。コードの正しさと実データの検証は別の作業。当たり前のことを改めて痛感した。

## 5. ここで正直に言っておきたいこと

これだけバグの話をしてきましたが、**私はプログラミングの知識がほぼありません。**

コードを自分で書いたことは一度もないです。それでもこのツールが完成したのは、**全てClaude Codeとの会話だけで解決したから**です。

「スクリプトは成功と言ってるのにファイルが空なんだけど」「6番目のツイートが違う人のになってる」「削除済みかと思ったら取れてないだけだった」

こうやって状況を言葉で伝えると、Claude Codeが原因を特定して、修正して、動作確認までやってくれる。

プログラミングの知識は、このツールを作るのに一切必要ありませんでした。「こういうものを作りたい」という意図と、「これがうまく動いていない」という観察力があれば十分でした。

7日間のデバッグ地獄も、実際には「Claude Codeとの7日間の会話」です。

## 6. 完成後：ブックマークが知識ベースに変わった

最終的な動作確認では、17件のブックマークを段階的スクロールで漏れなく取得し、各ツイートの詳細ページから本文・引用ツイート・外部リンクを抽出し、Google Driveへのアップロードまで問題なく通りました。

変わったことを正直に言うと、**ブックマークする行動の質が変わりました。**

以前は「なんとなく良さそうだからブックマーク」でした。でも今は「NotebookLMに入れる価値があるかどうか」を考えてブックマークするようになっています。

NotebookLMに「最近ブックマークした中でClaude Codeに関する情報をまとめて」と聞くと、自分がここ数週間で集めた情報を横断して答えてくれます。Xで見かけた記事、引用ツイートで発見した技術記事、外部リンクの内容——全部が一つの知識ベースに集まっている。

ブックマークがついに「資産」になった瞬間でした。
