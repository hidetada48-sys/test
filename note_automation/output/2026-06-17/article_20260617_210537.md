# Claude Codeで7人のAI参謀を作った話｜社員35名の現場

「生産も、仕入れ交渉も、お客さんとのやり取りも、労務も、全部ひとりでやってる」

これは、私自身のことです。

地方の中小メーカー（社員35名・創業60年超）で専務をしています。
生産の段取りから仕入れ交渉、顧客折衝、労務、総務まで。
頭の中と手帳だけで、会社のあらゆる判断を回してきました。

たとえば、取引先との商談の前。
「前回、何を約束したんだっけ」が思い出せず、古いメールと手帳を行ったり来たり。
気づけば30分。
そんなことが、週に何度もありました。

この記事は、そんな「ひとりで全部抱えている」私が、自分のためにClaude Codeで7人の"AI参謀"を作っている話です。

コーディングの話ではありません。
AIを「経営の参謀」にする話です。

同じように何役もこなしている人、AIを仕事で使いたいけど何から始めるか迷っている人に、具体的な設計の中身まで見せます。

## きっかけは「5人の参謀」を語る1本のブックマーク記事

すべては、Xでブックマークした1本の記事から始まりました。

@ObsidianOtaku さんの「勝手に賢くなるObsidianの作り方大全」という記事です。

内容をざっくり言うと、こうです。

「AIに毎回ゼロから状況を説明し直しているのは、共有記憶（AIが読める形でたまっていく業務メモ）がないからだ。これがあれば、AIは"事業を回す参謀"になる」

記事では、リサーチ・コンテンツ・クライアント・自己マネジメント・経理という「5人の参謀」が、同じルールブックを読みながら動く設計が紹介されていました。

これを読んだ瞬間、「これは自分のための仕組みだ」と思いました。

毎回ゼロから説明し直す問題。
記録したのに探し出せない問題。
全部、私自身が日々抱えているものでした。

そこから「自分の会社版の参謀を作ろう」と動き出したのが、この半年です。

## 「参謀」とは何か：コーディングしないClaude Codeの使い方

ここで使っているのが Claude Code です。

Claude Codeは「AIにプログラムを書かせるツール」だと思われがちです。
でも、実際はそれだけではありません。

私が作っているのは、コードを書くためのものではなく、**業務を覚えていて、聞けば答えてくれるAI**です。

これを「参謀（さんぼう）」と呼んでいます。
参謀とは、判断を助ける相談役のことです。

使い方はシンプルで、起点は全部「話しかけるだけ」。

> 「さっきの取引先との電話、こういう話だった。記録しておいて」
> 「明日の商談、前回までの経緯まとめて」
> 「今日やることは？」

ファイルを開いたり、フォームに入力したりする必要はありません。
話しかけると、AIが整理して覚え、必要なときに引き出してくれます。

大事なのは、その記録が**一箇所にたまっていく**ことです。
昨日の話も、先月の話も、半年前の話も、同じ場所に積み上がります。

だから「あの件、どうだったっけ」が消えました。

## 経営を支える7人の参謀という設計図

着想元は「5人の参謀」でしたが、うちの会社の業務に合わせて**7人**にしました。

```
経営参謀 ← 全体を見て大局的に判断する
├── 業界参謀   （業界動向・相場・競合）
├── 取引先参謀 （取引先との折衝記録）
├── 販売参謀   （販売実績の分析）
├── 現場参謀   （生産・設備のこと）
├── 経理参謀   （決算・月次の収支）
└── 労務参謀   （労務データ・期限アラート）
```

経営参謀を頂点に、6つの専門参謀がぶら下がる形です。

ポイントは、**全員が最初から完成しているわけではない**ということ。

すでに毎日バリバリ働いている参謀もいれば、まだ半人前の参謀、構想だけの参謀もいます。

「育てながら使う」。
これが一番しっくりきている進め方です。

完璧な設計を待っていたら、いつまでも始められません。
動くものから動かして、足りないところを足していく。

正直に言うと、最初に作った取引先参謀は、記録の粒度がバラバラで使い物になりませんでした。
でも「もっとこう書いて」と話しかけて直していくうちに、いまでは手放せない相棒になっています。
最初から完璧を狙わなかったのが、結果的に良かったんだと思います。

## この参謀システムの中核技術

ここで、エンジニアの人向けに「これは何でできているのか」を簡潔に書いておきます。
（技術の話に興味がなければ、この章は飛ばして大丈夫です）

一言で言うと、**「Claude Code を頭脳に、共有の指示書と"記憶"を持たせたもの」**です。

中核は次の3つ。

| 中核 | 役割 | これがないと |
|---|---|---|
| **Claude Code** | 頭脳。話しかけると考えて動く本体 | そもそも始まらない |
| **CLAUDE.md** | 全参謀が起動時に必ず読む"事業の憲法"。各参謀の役割・ルールを書いた共有の指示書 | 参謀ごとの一貫した判断ができない |
| **basic-memory** | 会話（セッション）をまたいで覚えている記憶層。「○○社の経緯は？」で過去を引き出す心臓部 | ただのチャットに戻る（毎回ゼロから説明） |

参謀の作り方そのものは、拍子抜けするほど地味です。

たとえば取引先参謀なら、CLAUDE.md（共有の指示書）に、こんな数行を書くだけ。

> あなたは取引先専門の参謀です。
> 折衝の記録は「日付・相手・決まったこと・次の宿題」の形で残してください。

これだけで、役割と記録のルールが固定されます。
あとは話しかけるたびに、その通りに動いてくれます。

これを支える周辺ツールはこんな顔ぶれです。

- **Git／GitHub**：記録の保管庫。同時に、2台のPC（Linux機とWindows機）で**記憶を同期**する役目も担う
- **Skill（スキル）**：各参謀の「仕事のやり方」を定義したファイル
- **フック（hooks）**：話しかけなくても**起動時に勝手に動く**仕組み（週次レポート生成・有給アラートなど）
- **MCP**：外部ツールをつなぐ規格。**Jina AI**（Web検索＝業界参謀）と**NotebookLM**（大量文書の深掘り）をつないでいる

一番の核を1つ挙げるなら、**`basic-memory`（記憶層）と `CLAUDE.md`（共有の指示書）** です。

着想元の記事が言っていた「共有記憶がないとAIは参謀にならない」の正体が、まさにここにあります。

## 毎日働いている参謀たち（業界・取引先・販売）

実際に毎日動いている3人を紹介します。

**業界参謀**は、毎週はじめに自動で情報収集をします。

主要な原材料の相場、燃料価格、法規制の動き、競合の動向。
これらを勝手に調べて、1枚のレポートにまとめてくれます。

先日は「主要原材料の卸値が約2年半ぶりに上昇」という動きをキャッチしてきました。
こういう情報が、頼まなくても毎週届く状態になっています。

**取引先参謀**は、45社との折衝記録を覚えています。

「○○社から値上げの問い合わせがあって、年間契約の対象外商品は値上げ了承になった」

こう話すだけで、整理して記録します。
「○○社の未対応の件は？」と聞けば、一覧で返ってきます。

いま、全得意先への一斉値上げ交渉が進行中ですが、その膨大なやり取りを参謀が追跡してくれています。

**販売参謀**は、数字の分析担当です。

販売管理システムから書き出したデータを渡すだけで、月次の分析資料（Excel）を自動で作ります。
人の手は、ほぼゼロ。

ある得意先の今年度の売上が前年比+8.0%で、そのうちのある主力商品が+34.2%で全体を引っ張っていた——。
そんな発見も、参謀が勝手に見つけてくれました。

## 一番の働き者は「労務参謀」だった

意外なことに、一番多機能に育ったのは労務参謀でした。

ひとりで総務・労務を兼任していると、抜け漏れが一番こわい領域です。
だからこそ、ここに力が入りました。

労務参謀がやってくれること:

- **有給休暇のアラート**：全社員の付与日数を自動で計算し、付与の前に教えてくれる
- **年次イベントの通知**：労働保険の年度更新、算定基礎届、人事考課、年末調整など9件を、対応開始の時期に合わせて知らせる
- **法改正の監視**：労務関連の法改正を毎月チェック。しかも「法律が変わりました」で終わらせず、「自社への影響はこれです」まで翻訳して教えてくれる

期限のある手続きを「うっかり忘れる」リスクが、ぐっと減りました。

ひとりで抱えていると、こういう"絶対に落としてはいけないボール"が一番の重荷です。
それを参謀が肩代わりしてくれる安心感は、想像以上でした。

## まだ半人前の参謀、構想中の参謀（正直に）

正直に書きます。
7人全員が活躍しているわけではありません。

**現場参謀**は、まだ自動化の仕組みは作っていません。
でも「話しかけて記録する」形ではもう使っています。

たとえば、主力設備が突発的に故障して、約45時間も生産が止まったトラブル。
その復旧の経緯を、時系列でまるごと記録しました。
設備の異音など「故障の予兆」も記録して、点検の判断材料にしています。

**経理参謀**は、まだ構想だけ。
決算資料が揃ったら着手する予定です。

**経営参謀**も、これからです。
他の参謀たちのデータがもっとたまってから、全体を横断して判断する頭脳として育てます。

「全部完成してから公開しよう」とは思っていません。
むしろ、未完成のまま走りながら直していくのが、この手の仕組みの正解だと感じています。

## 半年使ってわかったこと、次にやること

半年やってみて、一番変わったのは何か。

それは「過去のことを調べ直す時間」が、ほぼ消えたことです。

以前は、商談前に経緯を掘り起こすだけで毎回20〜30分。
それが、いまは話しかければ数秒で返ってきます。

あの取引先との経緯、先月の数字、去年の今ごろの設備トラブル。
全部、話しかければ出てきます。

ブックマークした記事にあった「共有記憶がないとAIに毎回説明し直すことになる」という指摘は、本当でした。
逆に言えば、記憶を一箇所にためる仕組みさえ作れば、AIは一気に頼れる存在に変わります。

そしてもう一つ。
作るうちに、面白さの中心が移っていきました。

最初は「AIに何をさせるか」でした。
今は「何を任せて、何は人間が判断するか、どう仕組みにするか」を設計することが、一番おもしろい。

もしあなたが、ひとりで何役もこなしているなら、最初の一歩はこれです。

**まず、1人だけ参謀を作る。**

全部を一度に作る必要はありません。
一番つらい業務、一番忘れたくない業務を1つ選んで、そこだけAIに覚えさせる。

やり方は、拍子抜けするほど単純です。
電話を切ったあと、その内容をAIに話しかけて記録させる。
次に同じ相手と話す前に「前回までの経緯まとめて」と聞く。
最初はこれだけで十分です。

私の場合、その1人目が取引先との折衝記録でした。
1人うまく動けば、2人目、3人目は自然に増えていきます。

あなたなら、どの業務から「参謀」を作りますか。
