## 「調べる」たびに、コンテキストが溶けていた

資料をコンテキストに貼り付ける。Claudeが読む。トークンが消える。

しかもClaudeは次のターンには忘れる。

また別の記事を貼り付ける。またトークンが消える。また忘れる。

PDFならもっとひどかった。5000字の資料を読み込ませただけで、会話の3分の1が埋まった。中身を聞く前にコンテキストが半分消えている。

そのうち気づいてしまった。

**「自分、調べるたびにトークンを溶かしてるな」**

Claude Codeは使いこなせていた。でも「リサーチ」の部分だけ、ずっと非効率なやり方を繰り返していた。

何かが根本的に間違っていると感じ始めたころ、Xのブックマークで1本の投稿に出会った。

## トークン1/10の衝撃——notebooklm-pyを知った日

@tetumemo さんの投稿タイトルが目に飛び込んできた。

**「Claude×NotebookLMで『トークン消費1/10』を実現するための全手順」**

1/10。

「Claudeがすぐ忘れる」「PDFを投げたら制限が来た」「トークン消費が激しい」——この3つを全部解決する、という。

自分が抱えていた悩みを、そのまま箇条書きにされたような感覚だった。

そこで知ったのが `notebooklm-py` というツール。**Claude CodeからNotebookLMをCLIで操作できる**Pythonライブラリだ。

NotebookLMはGoogleの無料リサーチツール。URLやPDFを最大50件登録しておくと、その内容を元に質問に答えてくれる。今まではブラウザで開いて、手でソースを追加して、手でチャットして——という作業を全部自分でやっていた。

仕組みはシンプルだった。

NotebookLMに資料を登録しておき、ClaudeはLMに質問するだけ。**資料がClaudeのコンテキストに入ってこない。だからトークンが飛ばない。**

すぐにインストールした。

## セットアップ：コマンド1行、あとは自然言語

```bash
uv tool install notebooklm-py --with playwright
```

これだけ。v0.3.4がインストールされ、セッション情報は `~/.notebooklm/browser_profile` に保存される。`notebooklm login` でGoogleアカウントにログインすれば準備完了。

コマンドラインから直接叩く方法もある。

```bash
notebooklm create "タイトル"                                      # ノートブック作成
notebooklm source add-research -n [ID] "検索ワード" --import-all  # 検索してソース追加
notebooklm ask -n [ID] "質問"                                     # 質問する
notebooklm note list -n [ID]                                      # メモ一覧
notebooklm note get -n [ID] [noteID]                              # メモ全文取得
```

ただし実際は、**コマンドを覚える必要がない。**

Claude Codeと組み合わせると、自然言語で動く。「ノートブック作って、GPT Image 2について検索してソース追加して、まとめて」と伝えるだけ。Claude Codeが裏でコマンドを組み立てて実行してくれる。

インストール直後に既存のノートブックへ質問してみた。ターミナルに回答が返ってきた瞬間、「あ、本当に動いてる」と思った。

## 実践：「どの画像生成ツールを使うべきか」をClaudeだけで調べた

翌日、さっそく本番のリサーチに使ってみた。

OpenAIから新しい画像生成ツール「GPT Image 2」が出たというニュースが気になっていた。もともと `generate_images.py` というスクリプトでGemini Nano Banana 2を使っていたが、WindowsにもLinuxにも汎用化できておらず、特定フォルダの中でしか動かない状態だった。

「GPT Image 2はAPIで使えるのか？Nano Bananaと比べて画質や料金はどうなのか？」

以前は2つの方法を使い分けていた。Claudeに直接資料を読ませるか、LMをブラウザで開いてソースを集めてチャットするか。前者はトークンが飛ぶ。後者はブラウザを行き来する手間がある。

notebooklm-pyはその2つを同時に解決する。LMの操作をClaudeのチャットから動かせる。トークンを消費せず、ブラウザも開かずに。

【画像:本文|「Claude Chat → LM操作 → 30ソース収集 → 回答」のワークフロー図。Google Materialアイコンと矢印で一方向フローを表現。白背景・Google Blue統一】

### ノートブックを作り、30ソースを集める

```bash
notebooklm create "GPT Image 2 vs NanoBanana Pro 比較調査"
# → ノートブックID: 34a78960
```

次にソースを集める。LMでリサーチするときは、いつもこうしている。検索クエリに媒体名を含めると、精度が約9割で絞り込める。

**検索クエリに媒体名を含めると、精度が約9割で絞り込める。**

| クエリ | 収集できる媒体 |
|---|---|
| `"GPT Image 2" note記事` | note記事 |
| `"GPT Image 2" YouTube` | YouTube |
| `"GPT Image 2"` | 一般web |

3回に分けてクエリを変えて検索し、合計30ソースを追加した。note記事・YouTube・一般webを媒体別に収集できるので、「どのジャンルの情報か」があとから把握しやすい。

LMでいつもやっているこの手順が、そのままClaudeのチャット画面から動いた。

### 30本のソースを元に、Claudeへ直接質問する

ここが一番感動した瞬間だった。

```bash
notebooklm ask -n 34a78960 "GPT Image 2とGeminiの画像生成、note記事用途ではどちらが優れているか"
```

ブラウザを開いていない。

なのに30本のソースを元にした回答がターミナルに返ってきた。

「自分、今ブラウザ一度も開いてないな」と気づいたとき、ちょっとニヤけた。

【画像:本文|「ブラウザ不要」を視覚化。大きな×マーク付きのブラウザアイコンと、光るClaudeチャット画面の対比。Google Red（×）とGoogle Blue（Claude）で強調】

### 回答をそのままmdファイルで受け取る

回答をLMのメモ機能に保存させ、そのまま取得することもできる。

```bash
notebooklm note get -n 34a78960 [noteID]
```

ブラウザのコピペ作業がゼロになった。30本分の情報を元にした調査結果が、そのままローカルのmdファイルとして積み上がっていく。

## GPT Image 2を断念してGeminiに決めた——1行で終わった話

調査の結果、GPT Image 2についてこんな情報が集まった。

- モデルID: `gpt-image-2`、OpenAI Python SDK経由でAPI利用可能
- 最大3840px、アスペクト比は3:1〜1:3で自由指定可能
- 料金: Low $0.006 / Medium $0.053 / High $0.21（1枚あたり）
- Batch APIで50%割引あり
- Canva・Adobe・HubSpot など商用SaaSで採用済み

**でも断念した。**

OpenAIの月額利用制限があり、安定した運用ができないと判断したからだ。毎日note記事を生成するような使い方をすると、途中で上限に引っかかる可能性がある。

一方でGeminiは：

- Google APIキーがすでにある
- 月額制限がない（従量課金）
- APIの呼び出し方が全く同じ形式

`gemini-3.1-flash-image-preview`（Nano Banana 2）から `gemini-3-pro-image-preview`（Nano Banana Pro）へ。コードを1行書き換えるだけで完了した。

「判断を下すための調査」が、これだけ速く終わる。

## 使い始めて変わった3つのこと

**① 「調べ方」そのものが変わった**

以前は「調べたい記事をClaudeに貼り付けて読ませる」だった。読み込むたびトークンが消え、次のターンには忘れ、また貼り直す——その繰り返しだった。

今は「LMにソースを積んでおき、ClaudeはLMに質問するだけ」になった。

Claudeのコンテキストに資料が入ってこない。トークンが飛ばない。しかも回答の根拠は30本のソースにある。質が下がるどころか、上がった。

**② 「調査→判断」の間にあった迷いが消えた**

「資料を読む→自分でまとめる→判断する」のステップが、「Claudeに質問する→返ってきた回答を判断する」だけになった。

自分でまとめる作業がなくなると、判断に集中できる。GPT Image 2 vs Geminiの選定も、30ソースを集めてから結論まで数時間で出せた。

**③ NotebookLMの全機能が、Claudeの画面だけで動くようになった**

これが一番大きな変化だった。

NotebookLMにはリサーチ以外にも機能がある。スライド資料・インフォグラフィック・フラッシュカード・音声解説——これらをブラウザ上で生成できる。

今は、それも全部Claudeのチャットから指示できる。

「このノートブックでフラッシュカード作って」「スライドにまとめて」と言えば、LMが生成して、Claudeがその結果を受け取って返してくれる。

Claudeのチャット画面だけで「ソース追加→質問→回答受け取り→メモ保存→スライド生成」まで完結する。

ブラウザに切り替える瞬間がなくなると、思っていたよりフローが途切れなくなる。「作業の途中でブラウザを開くストレス」が、こんなに大きかったのかと気づいた。

## まず1つ、今日のリサーチで試してほしい

```bash
uv tool install notebooklm-py --with playwright
notebooklm login
notebooklm create "最初のノートブック"
```

3行で使い始められる。

最初の感動は「ブラウザを開かずにLMに質問できた」だと思う。その次は「回答がmdで手元に来た」。そこから先は自然と使い道が広がっていく。

「調べ方が変わった」と感じるのは、たぶん最初のリサーチが終わった瞬間だ。
