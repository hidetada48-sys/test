## ① X Articles（そのままX Articles機能に貼る）

Claude CodeとsystemdでXブックマークの週次自動収集を組んだ。5日間動かなかった原因と、解決までの記録を書く。

## 1. Xのブックマーク、毎週自動で収集してGDriveに保存できたら？

Xのブックマーク、どんどん溜まっていませんか？

「あとで読もう」と思って保存したまま、どこかに消えていく。検索もしにくいし、整理する時間もない。

自分もそうでした。気づけば87件のブックマークが、未整理のまま眠っていた。

そこで作ったのが、**毎週自動でXブックマークを収集し、Markdownにまとめ、Google Driveに保存する仕組み**です。

Claude Code のスキル機能と systemd タイマーを組み合わせることで、毎週火曜の深夜0時に全自動で動くようにしました。

**この記事は Claude Code と Linux（systemd）を使っている方向けです。**

## 2. Claude Code×systemdで作ったXブックマーク自動収集の全体像

まず systemd タイマーが毎週火曜 00:00 JST に起動し、Claude Code の `x-bookmark-weekly` スキルを呼び出します。スキルが発動すると、Playwright が X にアクセスしてブックマーク一覧をスクロールしながら取得。収集したデータを週次統合 Markdown ファイルとしてまとめ、Claude がカテゴリ分類と概要付きのインデックスを自動生成します。最後に rclone で Google Drive の専用フォルダにアップロードし、Discord に完了通知が届く、という流れです。

実際に動かしたときの所要時間は**約12分**。Playwright でのスクロール取得から AI によるインデックス生成、GDrive アップロードまで、すべて自動で完了しました。

## 3. v1の限界と方針転換

最初に作った v1 は、シンプルな手動スクリプトでした。

そもそも「手動で毎回実行する」の時点で、継続しないのは目に見えていました。

v1 の課題を整理すると：

| 課題 | 内容 |
|------|------|
| 手動実行 | 毎回自分が実行しないと動かない |
| 出力が散乱 | 個別 txt で管理しにくい |
| 活用しにくい | NotebookLM より Claude に読ませる方が早い |

そこで v2 では「完全自動化」を設計の中心に置きました。

## 4. v2の設計：systemd × Claude Codeスキル × GDrive

v2 で変えたのは3つです。

**① 実行を自動化（systemdタイマー）**
毎週火曜 00:00 JST に自動起動するタイマーを設定しました。ログインしていなくても決まった時刻に起動します。

**② 出力を統合（週次 Markdown）**
個別ファイルをやめ、1週間分をまとめた1つの Markdown ファイルに統合しました。Claude が自動でカテゴリ分類・概要付きのインデックスも生成します。

**③ Claude Codeスキルとして定義**
`SKILL_V2.md` という形式でスキルを定義し、Claude Code から呼び出せるようにしました。

## 5. 詰まりポイント①：systemdはログインシェルの環境変数を引き継がない

v2 を実装してから5日後。systemd タイマーのログを確認したら、**一度も実行されていなかった**。

原因は「systemd はログインシェルのセッションとは独立している」という事実です。

`.bashrc` で設定した PATH は systemd には渡りません。HOME 変数も未設定。その結果、Claude CLI の認証トークンを見つけられず、起動直後に **401 認証エラー**で終了していました。

解決策はシンプルで、サービスファイルに環境変数を直接書くことです。最低限、以下の3つを書いておけば動くようになります。

- `HOME` にホームディレクトリのパスを設定する → 認証トークンを正しく参照できる
- `PATH` に必要なコマンドのパスをすべて列挙する → `claude`・`rclone`・`python3` が見つかる
- `TimeoutStartSec` を長めに設定する → AI 処理で時間がかかる場合に途中で強制終了されない

systemd で自動化するときは、**環境変数をサービスファイルに明示的に書く**のが鉄則です。

## 6. 詰まりポイント②：スキルファイルが ~/.claude/skills/ に未登録だった

`SKILL_V2.md` は test2 リポジトリの中に置いていました。しかし Claude Code がスキルとして認識するのは `~/.claude/skills/` 以下に登録されたファイルだけ。

リポジトリに置いてあるだけでは、スキルとして呼び出せません。`/x-bookmark-weekly` を呼び出しても、何も起きない状態でした。

解決策は、dotfiles 経由でシンボリックリンクを作ることです。実ファイルは test2 リポジトリに置いたまま、`~/.claude/skills/` にはシンボリックリンクを張ります。

## 7. 解決後のテスト：12分でフロー完走

2つの原因を修正した後、テスト実行しました。結果は成功。約12分で完了しました。

## 8. おまけ：Discord通知で「気づかない問題」を解消

完全自動化できたはいいものの、新たな問題が出てきました。「自動実行が完了しても、どこにも通知が来ない。いつ動いたかわからない」

そこで Discord の Webhook を使った完了通知を追加しました。収集件数とファイル名を含む通知が届くので、実行されたかどうかがすぐわかります。

## 9. まとめ

| 項目 | 内容 |
|------|------|
| 収集対象 | X（Twitter）のブックマーク |
| 実行タイミング | 毎週火曜 00:00 JST（systemdタイマー） |
| 出力形式 | 週次統合 Markdown + AI生成インデックス |
| 保存先 | Google Drive（X-Bookmarks-Weekly/） |
| 通知 | Discord Webhook |
| 所要時間 | 約12分 |

**詰まったポイント：**

1. **systemd は環境変数を引き継がない** → サービスファイルに HOME と PATH を明示する
2. **スキルファイルは `~/.claude/skills/` への登録が必要** → dotfiles 経由でシンボリックリンクを張る

自動化を組んだら、まず**本当に動いているかをログで確認する**ことをおすすめします。
