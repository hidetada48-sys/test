# 一次情報まとめ：notebooklm-pyでトークン消費を1/10にした話

作成日：2026-04-24

---

## この記事の核心体験

Claude Codeでリサーチするたびに資料をコンテキストに貼り付けてトークンを消費していた問題を、notebooklm-pyで根本解決した。
「ClaudeはLMに質問するだけ、資料はLMが参照する」構造にすることで、Claudeのコンテキストに資料が入ってこなくなった。

---

## 問題の実態

- 資料をコンテキストに貼り付ける → Claudeが読む → トークンが消える → 次のターンには忘れる
- PDFを読み込ませると5000字で会話の1/3が埋まる
- 「調べる」たびにコンテキストが溶けていく感覚があった

## 実践：GPT Image 2 vs Nano Banana Pro の比較調査

### 背景
- note記事用画像生成にGemini Nano Banana 2（gemini-3.1-flash-image-preview）を使っていた
- OpenAIのGPT Image 2が登場し、どちらを使うべきか判断できていなかった

### 手順
1. ノートブック作成：`notebooklm create "GPT Image 2 vs NanoBanana Pro 比較調査"` → ID: 34a78960
2. ソース収集：クエリに媒体名を含めて3パターンで検索、合計30ソース追加
   - `"GPT Image 2" note記事` → note記事
   - `"GPT Image 2" YouTube` → YouTube
   - `"GPT Image 2"` → 一般web
3. 質問：`notebooklm ask -n 34a78960 "GPT Image 2とGeminiの画像生成、note記事用途ではどちらが優れているか"`
4. ブラウザを一度も開かずに30ソース参照の回答がターミナルに返ってきた

### 発見：検索クエリに媒体名を含めると約9割の精度で絞り込める

---

## 結論：Gemini Nano Banana Proに決定

**GPT Image 2を断念した理由：** OpenAIの月額利用制限があり、安定運用できないと判断。

**Geminiを選んだ理由：**
- Google APIキーが既にある
- 月額制限がない（従量課金）
- APIの呼び出し方が全く同じ（コード変更1行で済んだ）

---

## 使い始めて変わった3つのこと

1. **調べ方が変わった**：資料をClaudeに貼る → LMに積んでClaudeはLMに質問するだけ
2. **調査→判断の迷いが消えた**：30ソースを元にした回答が即座に返ってくるので判断に集中できる
3. **NotebookLMの全機能がClaude画面だけで動く**：スライド・フラッシュカード・音声解説もチャットから指示できる
